For the Valio Aimo team

Laituri: where your customers' agents buy

An open front door (MCP and REST). A kitchen's own AI agent buys from Valio Aimo at a price Valio Aimo signs, inside limits the customer signs, with a record both sides can verify.

"How can a food-service wholesaler let autonomous purchasing agents place an order without exposing real systems, confidential data or the marketplace roadmap?"Your challenge, in your words

The problem you posed

Your customers' kitchens will soon send AI agents to buy for them. Valio Aimo cannot let an unknown agent order on a customer's account. A customer cannot let an agent spend without limits. Today there is no shared, checkable contract between the two.

Laituri is that contract. It is not a chatbot on the webshop. It defines what any agent may see, decide and be trusted with, on open standards Valio Aimo controls.

Your example request, end to end

"I need 1,000 litres of lactose-free milk by Monday."

  1. The agent searches. Laituri reads the claim lactose_free and turns 1,000 l into 1,000 x 1 l packs.
  2. Valio Aimo signs a fixed-price offer, valid 15 minutes, and checks it against the buyer's own words.
  3. The mandate allows it: the order confirms alone at €1,010.00 net for Monday. 1,600 litres would wait for the purchasing manager.

Three parties, one front door

The buyer

A hotel or school kitchen

  • Signs a mandate: limits, allergens, substitutes, and what the agent may do alone.
  • Runs the weekly order in one tap. Each line is green, orange or red, with a reason.
  • Approves a waiting line on a phone with one signed tap.
The buyer's agent

Any agent they choose

  • Claude Code, ChatGPT, Cursor, Gemini CLI or a custom script, over MCP or REST.
  • Searches, gets a signed offer, presents the mandate and orders, in Finnish, Swedish or English.
  • Never signs, approves or changes a price. It has no tool for it.
  • Plans events too: "a wedding for 80 guests on Saturday" gives three menus from Valio recipes.
Valio Aimo staff

The control side

  • Sees connected agents, what they bought and the demand it missed.
  • Answers questions an agent hands to a person.
  • Reads the same signed record as the buyer and can suspend an agent.

Why Valio Aimo and the customer can both trust it

Five controls on public standards (JWS signatures with ES256, public keys as JWKS, SHA-256). Any agent can check a claim without a manual check and without trusting our server.

1

Signed mandate

What the agent may do alone, what waits for a person, what is never allowed. 18 rules in three tiers.Buyer key signs
2

Signed offer

Fixed price, stock, date, cut-off, origin and labels. Valid 15 minutes, used once. Any edit breaks it.Valio Aimo key signs
3

Human approval

Orange lines go to a named approver. Approving re-checks the mandate and the stock.Approver key signs
4

Audit chain

Every step is a signed entry, chained by hash. A changed, deleted or reordered entry is named.Verified in the browser
5

Suspend

Valio Aimo can suspend any agent. Its key is then refused on every route and MCP call.Operator only
An agent can never set or change a price, an offer or a signature, approve an order, change the mandate, split an order to pass a limit, or follow instructions hidden in a request. Each attempt is refused and written to the record.

Nothing confidential leaves the server

  • The upstream API key stays on the server. No error names an upstream address.
  • No credential, no reads. An agent key reads only its own buyer's records.
  • Valio Aimo's overview counts which rule fired, never the customer's limits behind it.
  • A 20-line weekly order asks about only 228 of 17,546 products, in 10 requests.
